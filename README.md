# NodeArgus
1. Введение

**NodeArgus** — это веб-приложение для сканирования IP-адресов и подсетей, анализа открытых портов, определения ОС, провайдера, страны и поиска уязвимостей. Главная фишка — интерактивная карта-граф, где каждый узел — IP-адрес, а связи показывают соседство по подсети, общие DNS-имена или порты. При клике на узел отображается детальная информация и кнопка запуска сканера уязвимостей.

**Целевая аудитория**: специалисты по ИБ, пентестеры, системные администраторы, исследователи сети.


## 2. Ключевые функциональные требования

### 2.1. Модуль сканирования

- Принимает на вход: одиночный IP, диапазон CIDR (например, 192.168.1.0/24), список IP через запятую.
- Использует **Masscan** для быстрого сканирования портов (TCP SYN) и **Nmap** для детального анализа (определение ОС, версий сервисов, скрипты).
- **Безопасность**: сканеры вызываются исключительно через безопасные Python-обертки (`python-libnmap`, `masscan`), которые принимают аргументы как массивы. Использование `subprocess` с сырым пользовательским вводом запрещено для предотвращения Command Injection.
- Результаты сохраняются в БД с меткой времени.
- Сканирование выполняется **асинхронно**: пользователь не ждёт, получает уведомление по готовности.

### 2.2. База данных и хранение

- Хранит для каждого IP: геолокацию (страна, город, координаты), открытые порты (номер, протокол, сервис), ОС (по данным Nmap), время последнего сканирования.
- Геолокация определяется локально через базу **MaxMind GeoIP2** (или аналог), без обращения к внешним API при каждом скане.
- Хранит связи: IP1 – IP2, тип связи (например, `same_dns`, `common_port`).
- _Примечание_: Связи по подсети (`same_subnet`) не хранятся в БД, а вычисляются на лету на стороне бэкенда с использованием нативных операторов PostgreSQL для типа `inet`.
- Используется **PostgreSQL** (без PostGIS, гео-координаты хранятся как обычные `float`).

### 2.3. Веб-интерфейс (Single Page Application)

- **Главная страница**: поле ввода IP/подсети, кнопка «Сканировать», история последних сканов.
- **Страница результатов**: два режима:
    - **Табличный** — список всех найденных IP с фильтрацией по портам, стране, ОС.
    - **Граф** (основной) — интерактивная сеть на основе **D3.js**. Центральный узел — введённый IP или первый узел подсети. От него отходят линии к связанным узлам. При клике на узел — всплывающая панель с подробной информацией и кнопкой «Запустить поиск уязвимостей».
- При клике на «Поиск уязвимостей» запускается **Nuclei** (или NSE-скрипты) для выбранного IP, результаты отображаются в том же попапе.

### 2.4. Поиск уязвимостей

- Интеграция с **Nuclei** (ProjectDiscovery) — современный шаблонный сканер.
- Запуск по одному IP или по группе IP (выбранных вручную).
- Результаты: CVE ID, описание, уровень критичности, ссылка.
- Кеширование результатов, чтобы не пересканировать повторно в течение 24 часов.

### 2.5. Дополнительные фичи (бэклог)

- Экспорт результатов в CSV/JSON.
- Отчёты в PDF.
- Поддержка прокси и Tor для анонимного сканирования (опционально).

## 3. Технические требования

### 3.1. Бэкенд

- **Язык**: Python 3.11+ (основной).
- **Фреймворк**: **FastAPI** — асинхронный, с встроенной документацией Swagger.
- **Очереди задач**: **Celery** + **Redis** для асинхронного выполнения сканирования.
- **Сканеры**: вызываются через Python-библиотеки (`python-libnmap`, `python-masscan`).
- **API endpoints**:
    - `POST /scan` — запуск сканирования (возвращает `task_id`).
    - `GET /scan/{task_id}` — статус и результаты.
    - `GET /ip/{ip}` — детальная информация по IP.
    - `GET /graph/{ip}` — список соседей и связей для построения графа (включая вычисление подсетей на лету).
    - `POST /vuln/{ip}` — запуск Nuclei.

### 3.2. База данных

- **PostgreSQL 14+** (нативная поддержка типа `inet` для IP-адресов).
- Схема:
    - `ips` (id, ip_address [inet], country, city, latitude [float], longitude [float], provider, os, last_scan, created_at)
    - `ports` (id, ip_id, port_number, protocol, service, banner)
    - `links` (id, source_ip_id, target_ip_id, link_type [varchar], created_at) — _только для нетривиальных связей, не для подсетей_.
    - `vulnerabilities` (id, ip_id, cve_id, description, severity, found_at)

### 3.3. Фронтенд

- **Фреймворк**: **React**.
- **Библиотека графов**: **D3.js** (force-directed graph) с возможностью зумирования, перетаскивания.
- **Дополнительно**: **Leaflet** для отображения карты мира с метками IP (по координатам из БД).
- **Стили**: **Tailwind CSS** для быстрой вёрстки.

### 3.4. Инфраструктура

- **Контейнеризация**: **Docker** и **Docker Compose** для простого развёртывания (бэкенд, фронтенд, БД, Redis, Celery worker).
- **Система сборки**: для фронтенда **Vite**, для бэкенда **Poetry** (управление зависимостями).

## GeoIP Setup

NodeArgus использует локальную базу MaxMind GeoLite2-City и не обращается к
внешним API во время определения геолокации.

### Получение license key

1. Создайте бесплатную учетную запись на [странице регистрации MaxMind](https://www.maxmind.com/en/geolite2/signup).
2. В профиле MaxMind создайте license key для GeoLite2.
3. Сохраните ключ в `.env`:

```env
GEOIP_LICENSE_KEY=your-maxmind-license-key
GEOIP_MIRROR_URL=
GEOIP_DB_PATH=data/GeoLite2-City.mmdb
GEOIP_AUTO_UPDATE=false
```

### Первоначальная загрузка

```bash
python backend/scripts/download_geoip.py --license-key "$GEOIP_LICENSE_KEY"
```

Также можно вручную скачать архив GeoLite2-City с MaxMind, распаковать файл
`GeoLite2-City.mmdb` в `data/` и оставить `GEOIP_LICENSE_KEY` пустым.
Для автоматической загрузки из доверенного зеркала без ключа задайте URL
архива в `GEOIP_MIRROR_URL`.

### Автообновление

Для проверки срока базы создайте downloader и вызовите `update_if_needed()`.
Параметр `GEOIP_AUTO_UPDATE=true` предназначен для подключения этой проверки
к планировщику задач на следующем этапе проекта.
